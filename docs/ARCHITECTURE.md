## 🔄 Типичные операции (Use Cases)

### Use Case 1: Создание и выполнение ДЗ

```
┌─────────────────────────────────────────────────────────────┐
│ Teacher / Учитель                                          │
└────────────────┬──────────────────────────────────────────┘
                 │
        ┌────────▼────────┐
        │ 1. Создаёт ДЗ  │
        │    (HOMEWORKS)  │
        └────────┬────────┘
                 │
        ┌────────▼──────────────────┐
        │ Выбирает:                │
        │ • Предмет (subject)      │
        │ • Описание               │
        │ • Срок сдачи             │
        │ • Макс. баллов           │
        └────────┬──────────────────┘
                 │
        ┌────────▼────────────────────────┐
        │ 2. Ученик получает ДЗ          │
        │    (видит в своей вкладке)     │
        └────────┬─────────────────────────┘
                 │
        ┌────────▼────────────────────┐
        │ 3. Ученик выполняет ДЗ     │
        │    (начинает писать)        │
        └────────┬─────────────────────┘
                 │
        ┌────────▼──────────────────────────┐
        │ 4. Отмечается статус:            │
        │    • not_started → in_progress   │
        │    → submitted                   │
        │    (HOMEWORK_SUBMISSIONS)        │
        └────────┬───────────────────────────┘
                 │
        ┌────────▼────────────────────────┐
        │ 5. Учитель проверяет ДЗ        │
        │    Вносит:                      │
        │    • Баллы (0-10)              │
        │    • Оценку (2-5)              │
        │    • Комментарии               │
        └────────┬────────────────────────┘
                 │
        ┌────────▼────────────────────┐
        │ 6. Статус меняется на:     │
        │    "reviewed" (проверено)  │
        │    Ученик видит результат  │
        └─────────────────────────────┘
```

### Use Case 2: Анализ прогресса ученика

```
Teacher (Учитель)
       │
       ▼
Открывает Students
       │
       ├─► Кликает на Student
       │
       └─► Видит все связанные данные:
           │
           ├─ Lessons (все занятия ученика)
           ├─ Homework Submissions (все ДЗ)
           ├─ Assessment Results (все оценки)
           └─ Attendance (посещаемость)
               │
               ▼
           АНАЛИЗИРУЕТ:
           • Средняя оценка
           • Тренд (улучшается/ухудшается)
           • Проблемные предметы
           • Посещаемость
               │
               ▼
           СОЗДАЁТ Report
           для родителей
```

### Use Case 3: Планирование недели

```
Понедельник утром:

1. Открыть Lessons
2. Создать уроки на неделю:
   Пн: Математика (15:00, 7А)
   Пн: Математика (17:00, частный)
   Вт: Физика (15:30, 8А)
   ...

3. Открыть Homeworks
4. Создать ДЗ для каждого класса
5. Выбрать сроки сдачи
6. Добавить описание и баллы

Вторник-Пятница:
• После каждого урока отметить status=completed
• Добавить заметки и тему
• Указать посещавших в Attendance

Суббота:
• Проверить, кто не выполнил ДЗ
• Внести оценки за контрольные
• Обновить Reports
```

```

│          │                                                  │
```

```
           │
           ▼

│  │ • POST /api/v1/{table}                               │  │
│  │ • PATCH /api/v1/{table}/{id}                         │  │
│  │ • DELETE /api/v1/{table}/{id}                        │  │
│  └────────────────────────────────────────────────────────┘  │
│          │                                                  │
└──────────┼──────────────────────────────────────────────────┘
           │
           ▼

│  SQLite Database                                             │
│  storage/db/nocobase.sqlite                                  │

└──────────────────────────────────────────────────────────────┘

Пример MCP взаимодействия:
────────────────────────────────

Пользователь в Copilot Chat:
> "Создай домашнее задание по математике на завтра"

VS Code отправляет MCP серверу:
  {
    "jsonrpc": "2.0",
    "method": "tools/call",
    "params": {
      "name": "create_homework",
      "arguments": {
        "subject": "Математика",
        "dueDate": "2024-12-05"
      }
    }
  }

MCP сервер конвертирует в REST API вызов:
  POST http://localhost:13001/api/v1/homeworks
  Body: {
    "subject": "Математика",
    "dueDate": "2024-12-05"
  }

NocoBase API создаёт запись в БД
и возвращает результат

MCP сервер отправляет результат обратно в VS Code
Copilot Chat показывает результат пользователю
```

## 📈 Масштабирование данных

```
Типичный объём данных за год обучения:

Учитель (1 человек):
├─ Классы: 4 (7А, 7Б, 8А, 8Б)
├─ Ученики: ~20 классных + ~5 частных = ~25 всего
├─ Предметы: 4 (Математика, Физика, Геометрия, Вероятность)
│
├─ За год (в каждом классе 36 недель):
│  ├─ Занятия: 25 учеников × 36 недель × 2 урока/неделю = ~1800 записей
│  ├─ ДЗ: 25 учеников × 36 недель × 2 ДЗ/неделю = ~1800 ДЗ
│  ├─ Выполнение ДЗ: 1800 ДЗ × 25 учеников = ~45000 записей
│  ├─ Контрольные: ~4 контрольные × 4 предмета × 36 недель/год = ~144 контрольные
│  ├─ Результаты оценок: 144 контрольные × 25 учеников = ~3600 результатов
│  └─ Отчёты: 4 четверти × 25 учеников = 100 отчётов
│
└─ ИТОГО:
   • ~3500 занятий
   • ~45000 выполнений ДЗ
   • ~3600 результатов оценок
   • ~100 отчётов
   = ~52200 ЗАПИСЕЙ за год

Размер БД:
• SQLite файл: ~10-50 МБ (зависит от размера приложений/медиа)
• Без медиа: ~5 МБ достаточно

Производительность:
• Все операции должны быть практически мгновенными
• NocoBase хорошо оптимизирован для таких объёмов
• Можно без проблем добавить 5-10 учителей с теми же данными
```
